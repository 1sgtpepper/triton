## Resolved findings

The Gather partitioner's debug printer used to assert that every operation in a failed trial had an assigned dimension. Forward traversal can add the parent `scf.for` before an epilogue Gather rejects the trial, leaving a legitimate incomplete scheme. This was reproduced on the previous assertions-enabled Gather wheel using the existing `@gather_after_loop_falls_back` fixture and `TRITON_LLVM_DEBUG_ONLY=nvgpu-ws-data-partition`. The corrected printer labels such a dimension `<unassigned>`; the [lit fixture](https://github.com/1sgtpepper/triton/blob/3ccb92d230a78da486895b19321cb669e7b9a140/test/Hopper/WarpSpecialization/ws_gather_fallback.mlir) now executes that same debug path. The standalone Gather branch also initializes the atomic-sink pointer before checking whether a sink was found, eliminating the inherited undefined read that the Atomic branch had already fixed.

The two PRs now include executed, accepted-path H100 tests in their existing [Gather](https://github.com/1sgtpepper/triton/blob/3ccb92d230a78da486895b19321cb669e7b9a140/python/test/unit/language/test_warp_specialization.py) and [AtomicRMW](https://github.com/1sgtpepper/triton/blob/1d86ea9ec8f4210dcebec0347cda4d1b2c950b7c/python/test/unit/language/test_warp_specialization.py) test files. The Gather case uses descriptor inputs with `M=64, N=512, K=32`: a Gather feeds the dot, both `tt.gather` and `ttg.warp_specialize` remain in TTGIR, and actual output matches both ordinary execution and a PyTorch reference. The Atomic case uses the previous value returned by a block-uniform scalar atomic to select four distinct descriptor tiles; `tt.atomic_rmw` and specialization remain, the counter advances by `4 * 64`, and output matches both references. Preliminary H100 runs on production-source-equivalent prior wheels passed: [Gather](https://modal.com/apps/sgtpepper/main/ap-ENWfz1WgyjdeoJicp7MnYg) and [Atomic](https://modal.com/apps/sgtpepper/main/ap-ZoLhRshilNbPHUbyJVKKdC).

Two valid mixed kernels passed on the earlier integrated wheel: [both operations forcing fallback](test_gather_atomic_fallback.py), with separate output and atomic-effect oracles ([H100 result](https://modal.com/apps/sgtpepper/main/ap-ytv4Ya97d593HBubsmYsgK)); and [retained Gather plus accepted producer atomic](test_gather_atomic_positive.py), with both effects and specialization checked ([H100 result](https://modal.com/apps/sgtpepper/main/ap-mrTaKc6wZkWRaMaQ9eGV7X)). The integrated source retains Gather's `Unsupported` result propagation, then applies Atomic legality before accepting a candidate or beginning the structural rewrite.

## Deliberate limits

The old three-to-two-warp-group `Retry` path can retain generated task IDs; [#10436](https://github.com/triton-lang/triton/pull/10436) already owns that coupled retry and single-consumer bookkeeping issue. The new `Unsupported` fallback does not take that retry path. A post-rewrite cleanup failure is terminal by source control flow, but no deterministic valid fixture forces `applyPatternsGreedily` to fail after deletion; a test-only production switch would add surface for this rare branch. The [Gather maintainer's architecture objection](https://github.com/triton-lang/triton/pull/11988#pullrequestreview-5347572088) remains a review decision. Passing numerical tests cannot mark it resolved.

A nonzero masked-load `other` probe failed before reaching the suspected zero-fill lowering (`unsupported load type for producer commit`). It does not establish a masked-value miscompilation in these patches. A wide descriptor-output candidate miscomputed one half even without Gather; ordinary output storage made both the no-Gather control and the retained-Gather path correct. Neither observation is being attributed to these two narrow fixes.
